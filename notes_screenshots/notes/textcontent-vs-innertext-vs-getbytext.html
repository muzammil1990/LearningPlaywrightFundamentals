textContent vs innerText vs getByText

Playwright: reading text vs finding elements by text.

textContent() and innerText() read text from an element you already found.
getByText() finds an element by its text.
In everyday tests you often use them together.

Example

<div id="box">
  Hello <span style="display:none">Secret</span>
  <b class="shout" style="text-transform: uppercase">world</b>
</div>
<button>Sign in</button>
<button>Sign in with Google</button>
// READ text from an element you've already located
await page.locator('#box').textContent();  // "\n  Hello Secret\n  world\n"
await page.locator('#box').innerText();    // "Hello WORLD"

// FIND an element by its text
page.getByText('hello');                    // matches #box (case-insensitive, partial)
page.getByText('Sign in');                  // matches BOTH buttons (partial match)
page.getByText('Sign in', { exact: true }); // matches only the first button
page.getByText(/^sign in$/i);               // same idea with a regex

Using them together

// Find with getByText, then act on it
await page.getByText('Add to cart').click();

// Assert on found text (preferred, auto-retries)
await expect(page.getByText('Order placed')).toBeVisible();

// Find a container, then read its text
const msg = await page.locator('.alert').innerText();
expect(msg).toContain('Saved');

// Compare rendered text in an assertion
await expect(page.locator('#box')).toHaveText('Hello WORLD', { useInnerText: true });

Which to use

GoalUse
Click or check that an element with certain text existsgetByText()
Read visible text to store or compare in your own codeinnerText()
Read raw or hidden text, or text inside <script>textContent()
Assert text with automatic retryexpect(locator).toHaveText()

Cautions

  • getByText() is a substring match by default, so short text can match several elements. Use exact: true or a more specific locator.
  • It matches the smallest element that contains the text, so you usually get the inner <span> rather than its container.
  • For buttons, links, and inputs, getByRole() with a name is usually better than getByText(), because it also checks the element's role.
  • Because textContent() can return null, TypeScript may ask you to handle that case, for example (await box.textContent()) ?? ''.
  • allTextContents() and allInnerTexts() do the same as the single versions for every element a locator matches, and return an array.
